# Malicious DNS-over-HTTPS (DoH) Tunnel Detection

## Executive Summary
This repository contains the architecture and implementation of a **Hierarchical DNS-over-HTTPS (DoH) Threat Detection System**. The project focuses on identifying encrypted malicious traffic—specifically tunneling tools and DGA-driven malware—that bypasses traditional payload inspection by hiding within HTTPS streams.

To achieve real-time enterprise deployment speeds, the system implements the **MFS-DoH (Multi-Stage Feature Selection) parallel consensus methodology**, systematically reducing the network flow telemetry from 29 raw features down to an optimal, evasion-resilient subset of 5 features without statistically significant accuracy degradation.

## System Architecture

### Phase 1: Data Preprocessing & Hygiene (`Data_cleaning.py`)
* **Sanitization:** Aggressive handling of zero-division anomalies (`NaN` and `Inf` values) generated by network telemetry without relying on synthetic imputation, preserving exact packet timing distributions.
* **Leakage Prevention:** Stripped environment-specific metadata (Source/Dest IPs, Ports, Timestamps) to prevent model memorization and ensure cross-network generalization.
* **Datasets:** Processes multi-layer benchmark data (`l1-total-add.csv`, `l2-total-add.csv`, `l3-total-add.csv`).

### Phase 2: Parallel Consensus Feature Selection (`feature_selection.py`)
Replaces standard sequential filtering with a parallel consensus pipeline to evaluate all features across three distinct mathematical models simultaneously:
1. **LightGBM:** Captures complex, non-linear tree-based interactions.
2. **Hybrid ANOVA-Lasso:** Filters for strong linear variance and strictly eliminates redundant, highly correlated features using L1 regularization.
3. **Mutual Information (MI):** Extracts deep statistical dependencies and entropy.

Scores from all three evaluators are normalized (0-1 scale) and averaged to generate a Top 20 consensus list. A final Mutual Information refinement isolates the top 5 most discriminative features. 

### Phase 3: Hierarchical Classification (In Progress)
The final architecture will employ a soft-voting ensemble utilizing:
* **XGBoost:** For heavily regularized, generalizable decision boundaries.
* **CatBoost:** For ordered boosting and resistance to noisy adversarial data.
* **LightGBM:** For rapid, leaf-wise execution speed at scale.
* **Explainable AI (XAI):** Integration of SHAP (SHapley Additive exPlanations) for model transparency and feature impact analysis.
